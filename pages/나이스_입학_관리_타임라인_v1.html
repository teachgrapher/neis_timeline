      01A
      시도교육청 배정 직후평준화지역 교육감 전형

      시도교육청 배정자료 확인 및 전송 요청

      평준화지역 학교에 해당하는 업무이며, 교육감 전형은 시도교육청에서 대상학생을 일괄 배정해 주므로 학교에서는 배정 결과를 확인하는 것으로 시작한다. '본교확인'을 '대상'으로 선택해 저장해야 중학교로부터 기본 신상정보(사진 제외), 진로정보, 건강기록부가 넘어온다. 학교장 전형인 지역은 이 카드가 아니라 {개별추가}, {일괄추가}로 직접 등록한다.

      언제?
      학년말, 신입생 배정자료 및 신입생 명단을 확인하고 시도교육청이 입학생 배정자료를 등록한 뒤
      누가?
      입학 업무담당자
      어디서?
      [입학-입학관리-입학대상자관리]
      무엇을
      어떻게?
      [입학-입학관리-입학대상자관리]에서 '입학예정 학년도', '출신학교', '출신교상태', '본교확인', '자료도착', '학적반영', '전송상태' 확인 후 {조회}함 → {재학생} 탭에서 배정된 학생의 '본교확인'을 '대상'으로 선택 후 {저장}함('본교확인일괄선택'을 '대상'으로 선택 후 {저장}할 수 있음) → {전송요청}하여 출신 중학교로부터 배정자료의 '전송상태'가 '전송완료'인지 확인함.
      왜?
      신입생이 학교에 오기 전에 출신 중학교가 가진 신상·건강·진로 자료를 미리 받아 두어야 예비학적을 만들 수 있으므로.

      '본교확인' 세 가지 상태

      • 대상 — 본교 입학대상자인지를 확인하는 단계로 '대상'으로 선택하여 {저장}하면 중학교로부터 기본 신상정보(사진 제외), 진로정보(개인정보(진로 관련 사항) 활동 동의서에 동의한 졸업예정자에 한함), 건강기록부 등을 가져와 반영함.
      • 비대상 — 배정자료는 도착했으나 실제 입학대상자가 아닌 경우이며, '비대상'으로 {저장} 시 중학교로부터 받은 기본 신상정보(사진 제외), 진로정보, 건강기록부를 삭제하고 입학대상자에서 제외함.
      • 미확인 — 입학대상자에 대한 본교확인 상태가 미확인 상태임.
      • '본교확인'은 배정자료가 도착하면 수정이 가능하고, 고등학교에서 직접 입력한 학생의 경우 초기 상태는 '대상'임.

      '출신교상태'와 전송요청

      • 중학교에서 배정자료를 확인하면 '출신교상태'는 '확인', '본교상태'는 '대상'으로 활성화되고, '자료도착'은 도착일자가 표시됨(도착일자는 배정 학생의 건강기록부 및 기본 신상정보가 출신중학교로부터 배정 고등학교에 도착한 일시임).
      • 확인 — 출신학교에서 입학대상자의 배정학교와 학적사항을 확인한 상태임.
      • 미확인 — 출신학교에서 미확인한 경우로 글자에 마우스를 가져가면 출신교의 작업 상태가 말풍선으로 나타나며, '타교배정'인 경우는 해당 학생이 다른 고등학교로 배정된 경우이므로 필요시 중학교 담당자에게 본교 입학대상자 여부를 확인함. 예시로 출신학교가 사전일괄승인을 설정하지 않았거나 [진로지도-동의여부마감관리]에서 진로정보 학생동의서 학년 마감을 하지 않은 경우가 있음.
      • 오류 — 출신학교 입학대상자의 배정학교나 학적사항이 잘못되었음을 나타냄('오류' 글자 위에 마우스를 올리면 출신학교에서 작성한 오류 사유를 확인할 수 있음).
      • {전송요청}은 '본교확인' 항목이 '대상'인 학생 중 전송상태가 '미전송'인 학생에 대해 출신학교에 기본 신상정보(사진 제외), 진로정보, 건강기록부를 요청하는 기능으로, 출신학교에서 '사전일괄승인'을 설정해 둔 경우 자료가 자동 전송됨.
      • 출신 중학교에서 '사전일괄승인'한 경우 {전송요청} 시 '출신교상태'는 '확인', '자료도착'은 '도착일자', '전송상태'는 '전송완료'로 표시됨.
      • 등록된 학생이 본교 입학대상자가 아닐 경우 {삭제}함. {삭제} 시 지원학교의 배정결과도 삭제됨.
      • 중복된 학생 자료는 {삭제}하되, 삭제가 불가능할 경우 '본교확인'을 '비대상'으로 설정함.
      • 평준화지역 재배정 결과 반영 시, 해당학교에서 {개별추가} 또는 {일괄추가}로 직접 등록함.
      • 학적일괄생성 이후에는 {개별추가}, {일괄추가}, {전송요청}, {저장}이 표시되지 않으며, “학적일괄생성 작업이 완료되었습니다.”라는 메시지가 출력됨.

      02B
      배정자료 조회 후 누락 학생을 확인한 때교육감 전형·학교장 전형 공통

      {재학생} 탭 입학대상자 개별 추가

      시도교육청이 일괄 배정해주지 않는 학생이 있을 때 쓰는 방식입니다. 소규모 입학생, 해당 학교에 배정된 특수학생, 검정고시 학생, 별도로 배정된 체육특기생, 평준화지역 재배정 결과 반영 대상이 여기에 해당합니다. 당해학년도 중학교 3학년은 졸업처리를 완료했어도 {졸업생} 탭이 아니라 {재학생} 탭에서 검색하여 등록함.

      언제?
      학년말, 배정자료를 {조회}하여 입학대상자 중 누락된 학생을 확인한 뒤.
      누가?
      입학 업무담당자
      어디서?
      [입학-입학관리-입학대상자관리]
      무엇을
      어떻게?
      [입학-입학관리-입학대상자관리]에서 '입학예정 학년도', '출신학교', '출신교상태', '본교확인', '자료도착', '학적반영', '전송상태' 확인 후 {조회}하여 입학대상자 중 누락된 학생 유무를 확인함 → {재학생} 탭에서 {개별추가}를 클릭하면 나타나는 '개별추가' 창의 '입학담당자 정보'에서 '성명', '연락처'를 입력 → '학생찾기'에서 {학교찾기}로 출신중학교를 검색하고 '학년', '반', '성명'으로 {학생찾기} → '입학정보'에서 '과정', '계열', '학과'를 선택 → 학생목록에서 학생을 선택하여 추가한 후 {저장}함.
      왜?
      시도교육청 배정자료에 잡히지 않은 학생까지 명단에 올려, 예비학적 생성에서 빠지는 신입생이 생기지 않게 하려고.

      실무 메모

      • 본교 배정 학생에 대하여 {개별추가}로 학생을 추가하는 경우 '본교확인'은 '대상'으로 설정됨.
      • 타시도 재학생과 시도내 재학생은 {재학생} 탭에서 {개별추가}하고 졸업생은 {졸업생} 탭에서 {추가}함.
      • 현재학년도 중학교 3학년 학생은 졸업처리를 완료했어도 {재학생} 탭에서 검색하여 등록함. {재학생} 개별 등록 시 졸업처리와 상관없이 당해학년도 중학교 3학년은 재학생으로 추가함.
      • 이전학년도 졸업생이거나 부정확한 정보로 해당 학생이 없는 경우는 해당 학생을 찾을 수 없다는 메시지가 출력되며, 이 경우 해당 학생의 정보를 확인하고 다시 입력함.
      • 평준화지역 재배정 결과 반영 시, 해당학교에서 {개별추가} 또는 {일괄추가}로 직접 등록함.
      • '일괄추가' 창에서 '미존재'로 남는 학생은 학생정보가 잘못된 경우일 수 있으므로 {개별추가}를 이용하여 해당 학생의 검색 여부를 확인함.
      • 학적일괄생성 이후에는 {개별추가}, {일괄추가}, {전송요청}, {저장}은 표시되지 않으며, “학적일괄생성 작업이 완료되었습니다.”라는 메시지가 출력됨.

      {졸업생} 탭 이전학년도 졸업생 추가

      입학대상자 중 이전학년도에 중학교를 졸업한 학생이 있을 때만 하는 업무입니다. 이전학년도 졸업생은 교육감 전형이라도 시･도교육청에서 전송되지 않으므로 {졸업생} 탭에서 졸업생을 검색하여 추가함. 당해학년도 중학교 3학년은 이 탭이 아니라 {재학생} 탭에서 등록합니다.

      언제?
      학년말, 배정자료 확인과 {재학생} 탭 등록을 끝낸 뒤.
      누가?
      입학 업무담당자
      어디서?
      [입학-입학관리-입학대상자관리]
      무엇을
      어떻게?
      [입학-입학관리-입학대상자관리]에서 '입학예정 학년도', '출신학교', '출신교상태', '본교확인', '자료도착', '학적반영', '전송상태' 확인 후 {조회}함 → {졸업생} 탭에서 {추가} → '졸업생찾기' 창에서 {학교찾기}로 출신중학교를 검색하고 '졸업학년도', '성명'을 입력하여 {학생찾기} → '담당자', '전화번호'를 입력하고 '과정', '계열', '학과'를 선택한 후 {저장}함.
      왜?
      시도교육청 배정에서 아예 넘어오지 않는 이전학년도 졸업생을 명단에 올려, 출신중학교로부터 신상·건강 자료를 받아올 길을 열어두려고.

      실무 메모

      • 졸업학년도 정보가 불일치할 경우 해당 학생을 찾을 수 없으므로 학생정보를 확인하여 검색함.
      • {저장}하면 자동으로 해당 학생의 자료에 대해 출신중학교로 전송요청이 이루어짐.
      • 삭제 시 지원학교의 배정결과도 삭제되므로 {삭제}는 입력오류 건에만 사용함.

      04B
      재학생·졸업생 등록을 마친 뒤검정고시·특례입학·학력인정 대안학교 한정

      [입학-입학관리-입학자현황조회]에서 '입학예정 학년도' 확인 후 {조회}하여 입학자 현황을 확인하고 필요시 PDF, 워드, 엑셀, 파워포인트, 한글 문서로 저장하거나 출력함.
      왜?
      등록한 명단이 우리가 받기로 한 신입생 규모와 맞는지 학적일괄생성 전에 대조해 확인하려고.

      실무 메모

      • 본교의 입학대상자 현황을 출신 교육청, 출신학교별 재학생과 졸업생, 검정고시, 기타로 구분하여 조회함.
      • 조회된 입학자 현황은 '본교확인'이 '대상'인 학생의 인원수임. '비대상'이나 '미확인' 학생은 집계되지 않으므로 인원이 맞지 않으면 [입학-입학관리-입학대상자관리]에서 '본교확인' 상태를 다시 확인함.

      09D
      입학대상자 등록 완료 후반편성 선행 작업

      입학생 예비학적 일괄 생성

      입학대상자 명단 등록과 배정자료 수신을 모두 마친 뒤 진행하는 업무입니다. [입학-입학관리-입학대상자관리]에서 '본교확인' 상태가 '대상'인 학생에 대하여만 예비학적을 생성함. 생성된 학적은 0학년으로 만들어지며 이후 반편성과 진급처리로 이어집니다.

      언제?
      학년말, 입학대상자관리에서 '본교확인'을 '대상'으로 저장하고 출신학교 자료 전송이 완료된 뒤.
      누가?
      입학 업무담당자, 학적 업무담당자
      어디서?
      [입학-입학관리-학적일괄생성]
      무엇을
      어떻게?
      [입학-입학관리-학적일괄생성]에서 '대상자수(재학생, 졸업생, 검정고시, 기타)', '학적 생성자수' 등을 확인하고 {학적생성}하여 입학대상자의 학적을 0학년으로 생성함.
      왜?
      신입생이 학교 학적에 들어와 반편성과 학교생활기록부 작성을 시작할 수 있게 하려고.

      실무 메모

      • [입학-입학관리-입학대상자관리]에서 '본교확인' 상태가 '대상'인 학생에 대하여 예비학적을 생성함. 이때 전송받는 자료는 학교생활기록부 인적사항(사진 제외), 건강기록부, 진로희망 및 창의적 체험활동상황의 진로활동 특기사항(개인정보(진로 관련 사항) 활동 동의서 제출자), 학생･학부모서비스 신청 정보, 국가수준 학업성취도 결과임.
      • 예비 학적생성 시 '본교확인' 상태가 '비대상'으로 된 학생의 정보(보건, 학생 기본정보)는 일괄 삭제됨.
      • {학적생성}을 하면 '입학생'으로 학적이 생성되고 {학적생성취소}로 변경되며, [학적-반편성선행작업-진급대상자생성]에서 1학년 진급대상자로 생성하여 반편성을 할 수 있음.
      • [학적-진급대상자반편성관리-진급대상자반편성관리-대상자생성]에서 {진급자학적반영}하면 {생성} 또는 {생성취소}가 “진급대상자가 생성되어 있습니다.”로 변경됨.
      • 학적일괄생성 이후에는 {개별추가}, {일괄추가}, {전송요청}, {저장}은 표시되지 않으며, “학적일괄생성 작업이 완료되었습니다.”라는 메시지가 출력됨.
      • 예비 학적생성 이후 [학적-진급대상자반편성관리-진급대상자반편성관리]에서 입학생 반편성과 진급처리를 진행함.

      11E
      학적생성 이후필요시

      주민등록번호 오류·동명이인·졸업일자 점검

      예비학적을 생성한 모든 학교가 이어서 하는 점검 업무입니다. {학적생성} 이후에 열리는 진급대상자반편성관리 화면에서 입학생의 주민등록번호 오류와 동명이인을 확인하고, 출신학교 졸업일자가 틀린 경우 기본신상관리에서 수정합니다.

      언제?
      학년말, [입학-입학관리-학적일괄생성]에서 {학적생성}을 마친 뒤
      누가?
      학적 업무담당자
      어디서?
      [학적-진급대상자반편성관리-진급대상자반편성관리-대상자생성], [학적-진급대상자반편성관리-진급대상자반편성관리-개별반편성], [학적-기본학적관리-기본신상관리]
      무엇을
      어떻게?
      [학적-진급대상자반편성관리-진급대상자반편성관리-대상자생성]에서 {입학대상자관리}를 클릭하면 나타나는 '입학대상자관리' 창에서 {주민등록번호오류출력}으로 입학생의 주민등록번호 오류 여부를 확인함 → [학적-진급대상자반편성관리-진급대상자반편성관리-개별반편성]의 {입학생반편성내역개별등록} 탭에서 해당 학교의 입학생의 동명이인을 확인함 → 입학생의 출신학교 졸업일자의 수정은 [학적-기본학적관리-기본신상관리]의 {학적사항} 탭에서 수정함.
      왜?
      신입생의 학적이 반편성과 학교생활기록부로 넘어가기 전에 사람이 뒤바뀌거나 학력이 잘못 기록되는 일을 막으려고.

      • {학적생성} 이후 [학적-진급대상자반편성관리-진급대상자반편성관리-대상자생성]에서 {입학대상자관리}를 클릭하면 나타나는 '입학대상자관리' 창에서 {주민등록번호오류출력}으로 입학생의 주민등록번호 오류 여부를 확인함.
      • {학적생성} 이후 [학적-진급대상자반편성관리-진급대상자반편성관리-개별반편성]의 {입학생반편성내역개별등록} 탭에서 해당 학교의 입학생의 동명이인을 확인함.
      • 입학생의 출신학교 졸업일자의 수정은 [학적-기본학적관리-기본신상관리]의 {학적사항} 탭에서 수정함.

      10D
      학적생성 이후대상자 오류 발견 시

      학적생성취소 후 자료 재전송요청

      학적생성 후 대상자가 잘못 포함되었거나 빠진 것을 발견한 경우에만 하는 업무입니다. {학적생성취소}는 예비학적을 생성한 학생의 정보를 초기화함. 다만 '비대상'이었던 학생은 정보가 이미 삭제되어 취소만으로는 되살아나지 않습니다.

      언제?
      학년말, {학적생성}을 실행한 뒤 대상자 오류를 확인한 시점.
      누가?
      입학 업무담당자, 학적 업무담당자
      어디서?
      [입학-입학관리-학적일괄생성], [입학-입학관리-입학대상자관리]
      무엇을
      어떻게?
      [입학-입학관리-학적일괄생성]에서 {학적생성취소}하여 예비학적을 생성한 학생의 정보를 초기화함 → [입학-입학관리-입학대상자관리]에서 '본교확인' 상태를 '대상'으로 수정 후 {전송요청}하여 출신학교로부터 자료를 다시 받음 → 다시 [입학-입학관리-학적일괄생성]에서 {학적생성}함.
      왜?
      삭제된 학생 자료를 출신학교에서 다시 받아, 실제 입학하는 학생이 학적에서 빠지지 않게 하려고.

      실무 메모

      • {학적생성취소}는 예비학적을 생성한 학생의 정보를 초기화함.
      • 본교확인 상태가 '비대상'이었던 학생의 상태를 '대상'으로 수정 후 다시 {학적생성}을 해도 이 학생의 정보(보건, 학생기본정보)는 이미 삭제되어 학적생성 대상자에서 제외됨. 이러한 경우는 출신학교로 [입학-입학관리-입학대상자관리]에서 다시 자료를 {전송요청}해야 함.
